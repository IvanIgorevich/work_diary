# Правила рабочей отчётности

- Этот файл — общие правила для Codex и Claude. Новые указания пользователя
  сохранять в проекте, а не только в переписке или временных черновиках.
- Формат отчёта за несколько дней всегда хронологический:
  «План на день — Итог на день», затем такая же пара следующего дня.
  Не заменять пары списком одних итогов. После завершённых дней добавлять
  план на текущий день, если он запрошен; итог незаконченного дня не писать.
- Для сообщения в чат исключать уже отправленные части. Если план дня
  уже есть в чате, начинать с недостающего итога этого дня, затем давать
  пары следующих дней. Уже отправленный план не дублировать. В полном
  рабочем дневнике сохранять и план, и итог.
- Продолжать прежние ежедневные records/*.txt наряду с журналом и БД.
  При пропусках восстанавливать все завершённые рабочие дни, а не только
  дни последней выгрузки. Для текущего восстановления начало — 21.09.2026.
  Производные текстовые записи не импортировать повторно поверх часов
  из CSV/трекера; существующие архивные записи сохранять.
- В прежнем формате `records/*.txt` записываются только номера задач и
  потраченное на них время за день и накопительно. Отчётность, связь с
  командой, analysis, документация и другие пункты без номера задачи
  туда не входят. Их часы сохраняются в CSV/YAML, журнале и БД и входят
  в общие итоги дня, документ, сообщение для чата и таблицу времени.
- В отчётности четыре отдельные части:
  1. Google-документ «Отчёты»: планы, итоги, месячные отчёты.
  2. Рабочий чат: тот же текст «План — Итог».
  3. Таблица времени: приход, уход, перерывы и фактические часы.
  4. Рабочий дневник: структурированные данные и прежняя текстовая версия.
  Проверять каждую часть отдельно. Готовый черновик не означает, что
  документ исправлен, сообщение отправлено или часы внесены в таблицу.
- Номера задач проверять по Git и GitHub. Подзадачи сворачивать под
  подтверждённым родительским номером из data/tasks.yml. Общая задача
  техдолга — #7208 (https://github.com/domcap/Portal.Domcap/issues/7208).
  Не заменять номер одним названием и не угадывать связи между задачами.
- Созвоны с командой запланированы по понедельникам и пятницам.
  Пункт «связь с командой» включать в план только в эти дни.
- В остальные дни не добавлять созвоны в план. Если связь с командой
  была по факту, включать её время в итог по записи «Связь портал»
  из трекера независимо от дня недели и наличия пункта в плане.
- Отчёты сначала показывать пользователю для утверждения. Править
  Google-документ и таблицу времени только после явного указания
  пользователя на русском языке, относящегося к показанным правкам.
- Отправка сообщений и git push также требуют ясного указания на русском
  языке. «y», «yy», «ok», одиночные буквы и ввод в терминале не считаются
  подтверждением. Чат отправляет пользователь, если отдельно не поручил
  отправку агенту; sent ставить только после фактической отправки.
- Сохранять прежние records/*.txt и текстовый journal/*.md. Источники
  данных — CSV/YAML в data/, SQLite — пересоздаваемое представление для
  запросов и анализа. Не править БД и сгенерированный журнал независимо
  от источников. Сырые личные данные и доступы остаются в private/ вне git.

## Задачи по дням и план (с октября 2026)

- Основной план — техдолг #7208: пункт а) каждого дня. Другие задачи дня —
  отдельными пунктами б), в) …; в трекере это «Б портал», «В портал».
- Какие задачи были в какой день — по git в ~/Work/Portal.Domcap: ветка,
  открытая к началу дня, переключения веток (`git log -g`, reflog) и коммиты.
  Записывать в data/days.yml: `git:` — номера задач дня по git,
  `assign:` — если одна запись трекера захватывает две задачи, её время
  делится по моменту переключения ветки (from/to/item).
- Подзадачи #7208 — его sub-issues на GitHub, список в data/tasks.yml
  (проверен 17.10.2026). Не техдолг: #7243, #7386, #7509, #7516.
  gh-аккаунт IvanIgorevich не видит domcap — смотреть GitHub в браузере,
  где вход под рабочим аккаунтом ivan-zemchikov.

## Сообщение для рабочего чата

- Выдавать текст пользователю прямо в переписке: от первой неотправленной
  части до плана на сегодня — `bin/report telegram --plan-today`.
- Где заканчивается чат, отмечено в data/days.yml: `sent` — день отправлен
  целиком, `sent_parts: [plan]` — отправлен только план. Если пользователь
  говорит, чем заканчивается чат, — обновить эти отметки.
- Выгрузка трекера: ~/Downloads/Telegram Lite/report-ДД-ММ-ГГГГ.csv
  (подхватывается `bin/report`).

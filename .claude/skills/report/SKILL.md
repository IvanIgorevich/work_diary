# /report

Дневник: `~/Work/work_diary` (публичный GitHub-репозиторий). Всё делается через `bin/report` оттуда; README — там же.

Сначала прочитай `AGENTS.md`: это общие правила для Claude и Codex.
Проверяй четыре части отчётности отдельно: документ «Отчёты», рабочий чат,
таблица времени и локальный рабочий дневник. Не считать подготовленный
текст выполненной внешней записью или отправкой.

1. `bin/report` — подхватывает новые выгрузки трекера, составляет недостающие планы, печатает дни и отклонение от цели.
   Покажи пользователю таблицу дней и строку отклонения за месяц и неделю.
2. Если есть «план авто» или «непонятно: …»: покажи план дня (`data/days.yml`) и предложи поправить.
   Подсказки: задачи по веткам — в reflog `~/Work/Portal.Domcap`; подзадача → задача в отчётах — `data/tasks.yml`
   (новые связи спроси у пользователя и допиши туда). После правки снова `bin/report`.
3. `bin/report telegram` — выдай копируемый текст сообщения(й) целиком.
   Для каждого дня обязательна пара «План — Итог»; дни идут по порядку.
   Для чата не повторяй уже отправленные части: если план первого дня
   уже опубликован, начни с его итога. Полные пары остаются в дневнике.
   Если запрошен план текущего дня, добавь его после пар завершённых дней,
   без сегодняшнего итога. Созвоны в плане — только по понедельникам и пятницам;
   фактическая связь в остальные дни берётся из трекера и остаётся в итоге.
   Отправляет пользователь сам. Когда скажет, что отправил: `bin/report telegram --yes` (отметит дни).
4. Документ «Отчёты»: прочитай текущий раздел с учётом года и месяца,
   подготовь те же пары дней и план текущего дня. Существующие планы
   исправлять на утверждённые, недостающие итоги вставлять после их планов;
   не добавлять дубликаты. Сначала покажи текст и перечень изменений.
   Записывай только после явного русского указания пользователя; перед
   записью сохрани копию, после неё проверь результат и отметь `document`
   в `data/days.yml` для фактически внесённых дней.
5. `bin/report sheet` — покажи, что будет записано, и после ясного указания
   «да, записывай часы в таблицу» запусти `bin/report sheet --yes`.
6. Локальный дневник: проверь сохранение рабочих записей, планов и
   текстового журнала. `bin/report db` пересобирает производную SQLite-базу
   для запросов; обычное сохранение дневника обновляет её автоматически.
   Также проверь прежние ежедневные `records/*.txt`: пропуски нужно
   восстановить за весь недостающий период, а не только последний CSV.
   `bin/report backfill-records` дополняет их из канонических данных;
   сгенерированные записи не должны повторно добавлять часы при миграции.
7. Если начался новый месяц — `bin/report month` и отдай текст месячного отчёта.
8. `bin/report push` — покажи список файлов и сообщение коммита;
   после ясного указания «да, пушь» — `bin/report push --yes`.

Правила:
- Никогда не коммить ничего из `private/` и не добавляй в репозиторий личные записи трекера (сон, спорт и т. п.).
- Сегодняшний день не обрабатывай, пока пользователь не попросит (`--today`).
- Запись в таблицу и пуш — только после явного подтверждения в чате.
- Новые указания пользователя сохраняй в `AGENTS.md` и настройках проекта,
  чтобы их применяли оба агента. Не оставляй их только в переписке.
- Командные флаги `--yes` не являются подтверждением пользователя;
  использовать их можно только для уже явно разрешённого действия.
